# 🛍️ Django Web Market

Интернет-магазин на Django REST Framework с полным функционалом управления товарами, корзиной и заказами.

## 📋 Описание проекта

Проект представляет собой REST API для интернет-магазина с возможностью:
- Регистрации и авторизации пользователей
- Управления товарами (для администраторов)
- Работы с корзиной покупок
- Создания заказов с проверкой остатков и баланса
- Пополнения пользовательского баланса

Проект разработан с соблюдением принципов чистого кода, разделением бизнес-логики и представлений, покрыт тестами и полностью контейнеризирован.

## 🛠 Технологический стек

- **Python** 3.11+
- **Django** 4.2
- **Django REST Framework** 3.14
- **PostgreSQL** 15
- **JWT** аутентификация (SimpleJWT)
- **Docker** и **Docker Compose**
- **drf-spectacular** для автогенерации документации API

## 🚀 Быстрый старт

### Предварительные требования

- Docker
- Docker Compose

### Установка и запуск

1. **Клонируйте репозиторий:**
```bash
git clone <url-репозитория>
cd djangowebmarket
```

2. **Создайте файл .env в корне проекта:**
```env
SECRET_KEY =

POSTGRES_DB=webmarket
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres

DEBUG=True
```

3. **Запустите проект через Docker Compose:**
```bash
docker-compose up --build
```

4. **Дождитесь запуска сервисов. Приложение будет доступно по адресу:**
```
http://localhost:8081
```

5. **Создайте суперпользователя (опционально):**
```bash
docker-compose exec web python manage.py createsuperuser
```

## 🔑 Основные эндпоинты API

### Аутентификация

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| POST | `/api/register/` | Регистрация нового пользователя |
| POST | `/api/token/` | Получение JWT токена (логин) |
| POST | `/api/token/refresh/` | Обновление JWT токена |

### Пользователь

| Метод | Эндпоинт | Описание | Авторизация |
|-------|----------|----------|-------------|
| GET | `/api/profile/` | Получить профиль текущего пользователя | Требуется |
| POST | `/api/balance/top-up/` | Пополнить баланс | Требуется |

### Товары

| Метод | Эндпоинт | Описание | Авторизация |
|-------|----------|----------|-------------|
| GET | `/api/products/` | Список всех активных товаров | Не требуется |
| POST | `/api/products/create/` | Создать товар | Только админ |
| PATCH | `/api/products/{id}/` | Обновить товар | Только админ |
| DELETE | `/api/products/{id}/` | Удалить товар | Только админ |

### Корзина

| Метод | Эндпоинт | Описание | Авторизация |
|-------|----------|----------|-------------|
| GET | `/api/cart/` | Получить текущую корзину | Требуется |
| POST | `/api/cart/add/` | Добавить товар в корзину | Требуется |
| PATCH | `/api/cart/update/{product_id}/` | Обновить количество товара | Требуется |
| DELETE | `/api/cart/remove/{product_id}/` | Удалить товар из корзины | Требуется |

### Заказы

| Метод | Эндпоинт | Описание | Авторизация |
|-------|----------|----------|-------------|
| POST | `/api/orders/create/` | Создать заказ из корзины | Требуется |

## 💡 Примеры использования API

### 1. Регистрация пользователя

```bash
curl -X POST http://localhost:8081/api/register/ \
  -H "Content-Type: application/json" \
  -d '{
    "email": "user@example.com",
    "password": "securepassword123",
    "password2": "securepassword123"
  }'
```

### 2. Получение JWT токена

```bash
curl -X POST http://localhost:8081/api/token/ \
  -H "Content-Type: application/json" \
  -d '{
    "email": "user@example.com",
    "password": "securepassword123"
  }'
```

Ответ:
```json
{
  "access": "eyJ0eXAiOiJKV1QiLCJhbGc...",
  "refresh": "eyJ0eXAiOiJKV1QiLCJhbGc..."
}
```

### 3. Пополнение баланса

```bash
curl -X POST http://localhost:8081/api/balance/top-up/ \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <access_token>" \
  -d '{
    "amount": "1000.00"
  }'
```

### 4. Добавление товара в корзину

```bash
curl -X POST http://localhost:8081/api/cart/add/ \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <access_token>" \
  -d '{
    "product_id": 1,
    "quantity": 2
  }'
```

### 5. Создание заказа

```bash
curl -X POST http://localhost:8081/api/orders/create/ \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <access_token>"
```

## 🏗️ Архитектура и бизнес-логика

### Разделение ответственности

Проект следует принципу разделения ответственности:

- **models.py** — модели данных и их связи
- **views.py** — обработка HTTP-запросов, валидация входных данных
- **services.py** — бизнес-логика (создание заказов, пополнение баланса)
- **serializers.py** — сериализация и десериализация данных
- **permissions.py** — проверка прав доступа

### Ключевые особенности

1. **Транзакционность**: Все критичные операции (создание заказа, пополнение баланса) выполняются в транзакциях
2. **Блокировки**: Используется `select_for_update()` для предотвращения race conditions
3. **Логирование**: Все важные действия логируются
4. **Валидация**: Многоуровневая валидация данных (модели, сериализаторы, бизнес-логика)
5. **Кастомные исключения**: Понятная обработка ошибок через специализированные исключения

### Процесс создания заказа

При создании заказа выполняются следующие проверки и действия:

1. Проверка, что корзина не пуста
2. Блокировка записей товаров для предотвращения race conditions
3. Проверка достаточности товара на складе
4. Проверка достаточности средств на балансе пользователя
5. Списание средств с баланса
6. Создание заказа
7. Создание позиций заказа
8. Обновление остатков товаров на складе
9. Очистка корзины
10. Логирование успешного создания заказа

## 🔒 Безопасность

- JWT аутентификация с коротким временем жизни токенов (15 минут для access token)
- Пароли хешируются с использованием встроенных механизмов Django
- Права доступа разграничены: обычные пользователи и администраторы
- CSRF защита включена
- Валидация всех входных данных

## 📝 Логирование

Проект использует стандартный модуль `logging` Python. Все важные события логируются:

- Создание заказов
- Пополнение баланса
- Ошибки при недостаточности товара или средств
- Изменение остатков товаров

Логи выводятся в консоль (можно настроить запись в файл в настройках).

## 📊 Модели данных

### User (Пользователь)
- `email` — email адрес (уникальный, используется для входа)
- `balance` — баланс счета (Decimal)
- `is_staff` — является ли администратором

### Product (Товар)
- `name` — название товара
- `description` — описание
- `price` — цена (Decimal)
- `stock` — количество на складе
- `is_active` — активен ли товар

### Cart (Корзина)
- `user` — связь с пользователем (OneToOne)

### CartItem (Элемент корзины)
- `cart` — связь с корзиной
- `product` — связь с товаром
- `quantity` — количество

### Order (Заказ)
- `user` — связь с пользователем
- `status` — статус заказа ('pending', 'paid')
- `total_price` — общая стоимость
- `created_at` — дата создания

### OrderItem (Элемент заказа)
- `order` — связь с заказом
- `product` — связь с товаром
- `price` — цена на момент покупки
- `quantity` — количество
